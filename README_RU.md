# FerroScout

FerroScout — небольшая локальная утилита на Rust для статического анализа безопасности исходного кода и конфигурационных файлов. Она ищет некоторые опасные шаблоны и показывает находки с путём к файлу, номером строки, фрагментом доказательства и рекомендацией по исправлению.

Это ранняя rule-based версия. Она не строит полноценные AST и не доказывает возможность эксплуатации. Считай результаты поводом для ручной проверки, а не подтверждёнными уязвимостями. Чистый отчёт не гарантирует безопасность приложения.

## Сборка

Установи стабильный Rust toolchain и выполни:

```bash
cargo generate-lockfile
cargo fmt --all
cargo fmt --all -- --check
cargo test --all-targets --locked
cargo clippy --all-targets --locked -- -D warnings
cargo build --release --locked
```

Бинарный файл появится в `target/release/ferroscout`.

## Использование

```bash
# Проверить каталог
ferroscout scan ./project

# Проверить один файл
ferroscout scan ./src/main.rs

# Вывести отчёт в JSON
ferroscout scan ./project --format json

# Показать только Medium и High
ferroscout scan ./project --severity medium

# Исключить дополнительные каталоги или относительные пути
ferroscout scan ./project --exclude fixtures --exclude generated

# Изменить максимальный размер файла (в байтах)
ferroscout scan ./project --max-file-size 1048576

# Посмотреть список реализованных правил
ferroscout rules
```

Код завершения: `0` — выбранных находок нет и контекста достаточно; `1` — найдены проблемы; `2` — сканирование не удалось выполнить полностью или контекста недостаточно.

## Реализованные проверки

| Правило | Что ищет | Ограничение |
|---|---|---|
| `FS-SECRET-001` | Похожие на секреты присваивания и PEM-маркеры приватных ключей | Фильтр заглушек простой; проверь, настоящий ли это секрет |
| `FS-XSS-001` | Маркер недоверенного ввода рядом с динамическим HTML sink | Проверяется короткое окно строк, полноценного taint analysis нет |
| `FS-INJECT-001` | Динамическую сборку SQL и некоторые вызовы shell | Нужно вручную проверить bind-параметры и валидацию ввода |
| `FS-PATH-001` | Недоверенный ввод рядом с файловыми операциями | Не анализируется семантика путей и проверка выхода за корневой каталог |
| `FS-SSRF-001` | Недоверенный ввод рядом с серверным HTTP-запросом | Не анализируются DNS, редиректы и сетевые ограничения |
| `FS-CORS-001` | Отражение origin в файле с включёнными credentials | Нужно проверить фреймворк и реальную конфигурацию |
| `FS-DESER-001` | Некоторые небезопасные API десериализации | Не определяется, контролирует ли вход атакующий |
| `FS-TLS-001` | Явное отключение проверки TLS-сертификатов | Тестовая настройка может быть намеренной; проверь production |
| `FS-DEBUG-001` | Типичные настройки debug-режима | Не устанавливается, включена ли настройка в production |
| `FS-CRYPTO-001` | Некоторые варианты слабого хеширования паролей и генерации токенов | Назначение каждого хеша или случайного значения не выводится автоматически |

Первая версия использует консервативные построчные шаблоны, а не языковые парсеры. Она может пропускать многострочные потоки данных и находить шаблоны, безопасные в более широком контексте. Правило IDOR пока не включено: для надёжной проверки нужны понимание владения ресурсами и логики авторизации между маршрутами и слоями доступа к данным.

## Поведение и приватность

- Читает файлы локально и не обращается к сети.
- Не запускает проверяемые программы, shell-команды, скрипты или сборочные процессы.
- Не изменяет и не удаляет файлы.
- Не переходит по символическим ссылкам при обходе каталога; если сам путь сканирования является симлинком, он отклоняется.
- Пропускает бинарные файлы и файлы больше заданного лимита (по умолчанию 2 МиБ; максимум 16 МиБ).
- Проверяет распространённые расширения исходников и конфигураций, а также `.env`, `.env.*` и `Dockerfile`. Также распознаются распространённые файлы `.lock`, `.http`, `.har` и `.txt`.
- По умолчанию исключает `.git`, `target`, `node_modules`, `vendor`, `dist`, `build`, виртуальные окружения и Python cache.
- Маскирует похожие на секреты значения в доказательствах. Это не заменяет запрет на хранение секретов в репозитории.

## Статусы отчёта

JSON-отчёт содержит один из статусов:

- `FINDINGS_FOUND` — после фильтра severity осталась хотя бы одна находка.
- `NO_ISSUES_FOUND` — проверен хотя бы один поддерживаемый файл, ошибок сканирования нет, а выбранные проверки не нашли проблем.
- `INSUFFICIENT_CONTEXT` — не найдено поддерживаемых файлов или ошибки помешали завершить проверку.

`NO_ISSUES_FOUND` означает только, что реализованные проверки не нашли проблему в заданной области. Это не означает, что приложение безопасно.


Используй только синтетические тестовые данные. Не добавляй настоящие пароли, токены или приватные ключи в тесты и примеры.
